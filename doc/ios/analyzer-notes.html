§ 01

iOS의 오버레이 제약

iOS는 Android와 달리 시스템 전역 오버레이를 허용하지 않는다. Android의 SYSTEM_ALERT_WINDOW에 대응하는 권한이 없고, Facebook Messenger 채팅 헤드 같은 플로팅 위젯은 App Store 심사에서 거부된다. 샌드박스 보안 모델 때문이다.

대신 iOS에는 "오버레이스러운" 효과를 낼 수 있는 공식 API들이 있다.

  • Picture in Picture — AVSampleBufferDisplayLayer로 임의 콘텐츠를 PiP 창에 그릴 수 있지만, 백그라운드 진입 시점 제약과 오디오 세션 필수 등 까다로움
  • Live Activities & Dynamic Island (iOS 16.1+) — 잠금화면·다이내믹 아일랜드에 정보 표시. 가장 "오버레이에 가까운" 공식 수단
  • Widgets (WidgetKit) — 홈/잠금화면 위젯. iOS 17부터 AppIntent로 인터랙션 가능
  • 앱 내부 오버레이 — 자기 앱 안에서는 자유
  • Broadcast Upload Extension — 화면 공유 중에 한해 시스템 전반에 작은 UI 표시 가능
핵심 제약

iOS 앱은 절대로 다른 앱(게임)의 화면 픽셀을 직접 읽을 수 없다. 안드로이드식 "게임 위에 떠 있는 도우미" 구조는 처음부터 불가능. 우회 경로로 가야 한다.

§ 02

현실 점검 — 무엇이 가능한가

라이엇은 Wild Rift 공식 API를 제공하지 않는다 (PC LoL은 있지만 모바일은 없음). "소환사명으로 매치 정보 조회" 같은 깔끔한 길은 막혀 있고, 화면 인식 + 정적 데이터 매칭으로 가야 한다.

로딩 화면에서 알 수 있는 것

✓ 가능

챔피언 5명 · 소환사 스펠 2개씩 · 소환사명/랭크 · 챔피언별 기본 궁 쿨타임 (레벨 1/6/11/16)

✗ 불가

실시간 궁 쿨타임 — 아이템(아이오니아 장화, 군주의 명령), 룬(감응의 돌), 어빌리티 헤이스트로 결정되므로 인게임에서만 추적 가능

로딩 화면에서 줄 수 있는 가장 큰 가치는 "라인전 플랜". 챔피언/스펠 조합만 알아도 절반은 짜진다.

§ 03

단계별 접근

MVP1단계 · 로딩 화면 스크린샷 분석

사용자가 로딩 화면에서 스크린샷 한 번 → 공유 시트로 앱에 전달 → 분석. 가장 빠른 검증 경로이자 사용자에게 줄 수 있는 가장 큰 가치.

1

좌/우 팀 분할

로딩 화면 레이아웃은 고정 — 상대 좌표 기반으로 챔피언 슬롯 5개 크롭

2

챔피언 식별

각 슬롯 ROI → VNFeaturePrintObservation + 챔피언 아이콘 DB와 코사인 유사도 매칭

3

스펠 인식

챔피언 옆 스펠 아이콘 2개 크롭 → 10여 종 스펠 DB와 매칭 (매우 쉬움)

4

분석 출력

"다리우스(점멸/점화), 야스오(점멸/유체화)..." + 궁 기본 쿨타임 · 카운터 · 파워 스파이크 레벨

EXT2단계 · 인게임 추적 (욕심 단계)

ReplayKit Broadcast Extension으로 게임 중 화면을 받아 상대 궁 사용 감지 → Dynamic Island에 카운트다운. 가장 현실적인 건 수동 트리거 하이브리드 — 사용자가 상대 궁 본 순간 Dynamic Island 탭으로 타이머 시작. UX는 덜 매끈하지만 인식 오류가 없다.

주의

Broadcast Extension은 메모리 한도 ~50MB. 발열·배터리 부담도 있고, 무엇보다 Riot의 서드파티 정책 문제가 있다. 챔피언 식별만 자동화하고 쿨타임은 수동 트래커로 두는 게 안전.

§ 04

화면 인식 파이프라인

챔피언 아이콘 DB

와일드리프트 챔피언 100명+. 공식 위키에서 아이콘 이미지를 받아 정사각형 정규화 → 각 이미지의 VNFeaturePrintObservation 벡터를 미리 계산해 앱에 번들. 런타임엔 크롭 ROI의 feature print만 뽑아 nearest neighbor 검색. 100개 비교가 1ms 이내. CoreML 학습 없이도 정확도 양호하고, 새 챔피언은 이미지 한 장으로 추가 가능.

스킨이 변수다. 로딩 화면은 선택 스킨의 스플래시 일부가 들어가서 기본 아이콘과 다를 수 있음 → 주요 스킨 아이콘도 DB에 함께 넣고 "어떤 스킨이든 챔피언 X로 매핑".

ROI 좌표

iPhone 해상도/노치 종류마다 픽셀 좌표가 다르므로 상대 좌표(이미지 너비/높이 비율)로 저장. 와일드리프트는 가로 고정이라 회전 처리 불필요. 노치/다이내믹 아일랜드 기종은 좌측 첫 챔피언 박스 중심만 한 번 캘리브레이션하면 나머지는 등간격으로 계산.

§ 05

시작하기

가장 빠른 검증 경로:

i

로딩 화면 샘플 수집

다양한 기종·스킨으로 스크린샷 5~10장

ii

ROI 좌표 잡기

Python + Pillow로 챔피언 슬롯 잘라보며 안정성 눈으로 확인

iii

iOS PoC

PHPickerViewController로 사진 받기 → VNFeaturePrintObservation으로 매칭

iv

정보 DB 연결

챔피언별 궁 쿨타임·카운터·팁 데이터 붙여 결과 화면 제작

v

공유 익스텐션

스크린샷 찍자마자 바로 분석되게 Share Extension 추가

권장

처음부터 Broadcast Extension은 지양 — 50MB 메모리 제한, lldb 디버깅 번거로움 때문에 핵심 가치인 인식 품질에 집중하기 어렵다. 수동 스크린샷 임포트로 파이프라인 검증부터.
